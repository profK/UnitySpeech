# Binary Protocol Specification

The worker's HTTP responses use a custom length-prefixed binary protocol. This protocol is designed for streaming audio synthesis with low latency and boundary tolerance.

## Record Format

Every record has the same wire layout:

```
┌───────────┬──────────┬──────────┬──────────────────────────┐
│  Type (1) │  Length  │ Payload  │  Padding (to 8-byte)     │
│  (uint8)  │ (uint32) │  (bytes) │                         │
└───────────┴──────────┴──────────┴──────────────────────────┘
```

- **Type**: Single byte identifying the record type
- **Length**: 4-byte little-endian integer; length of the payload only (excludes type, length, and padding bytes)
- **Payload**: Record-specific data
- **Padding**: Zero bytes to align the total record to an 8-byte boundary

The total on-wire size of a record is: `1 + 4 + length + padding`.

## Record Types

| Byte | Name | Purpose |
|------|------|---------|
| `0x01` | START | Begin of a speech response |
| `0x02` | PCM | Audio data chunk |
| `0x03` | END | End of response with timing metadata |
| `0x04` | ERROR | Error condition |

## START Record

Signals the beginning of a speech response. The client uses this to initialize buffers and track metadata.

**Payload Layout:**
```
┌──────────┬─────────────────┬─────────────────┬───────────────┬──────────────┐
│ Version  │  Voice ID len   │  Voice ID       │ Language len  │ Language     │
│ (uint8)  │  (uint16 LE)    │  (UTF-8 bytes)  │ (uint16 LE)   │ (UTF-8 bytes)│
├──────────┼─────────────────┼─────────────────┼───────────────┼──────────────┤
│ Duration │ Sample Rate                                          │
│ (float64)│ (uint32 LE)                                          │
└──────────┴──────────────────────────────────────────────────────┘
```

**Fields:**

| Field | Type | Description |
|-------|------|-------------|
| `version` | uint8 | Protocol version (currently 1) |
| `voice_id` | len16 + UTF-8 | Voice ID used for synthesis |
| `language` | len16 + UTF-8 | Language code (e.g., "en", "ja", "zh") |
| `duration_s` | float64 LE | Estimated speech duration in seconds |
| `sample_rate` | uint32 LE | Audio sample rate (24000 Hz) |

## PCM Record

Carries audio data. Multiple PCM records stream in sequence between START and END.

**Payload Layout:**
```
┌──────────────────┬──────────────┬──────────────┐
│ Sample Offset    │ PCM Length    │ PCM Bytes    │
│ (uint64 LE)      │ (uint32 LE)   │ (raw int16 LE)│
└──────────────────┴──────────────┴──────────────┘
```

**Fields:**

| Field | Type | Description |
|-------|------|-------------|
| `sample_offset` | uint64 LE | Contiguous sample index (0 for first chunk, increments by chunk size) |
| `pcm_length` | uint32 LE | Number of raw PCM bytes that follow |
| `pcm_bytes` | raw | 16-bit signed little-endian samples, mono |

**Audio Format:**
- Sample rate: 24,000 Hz
- Channels: 1 (mono)
- Sample format: 16-bit signed integer, little-endian
- Default chunk size: 480 samples (20 ms at 24 kHz)

## END Record

Signals the end of a speech response. Includes timing metadata measured by the worker.

**Payload Layout:**
```
┌──────────────┬─────────────┬───────────────┬────────────────┐
│ Total Samples│ Wall Time   │ Inference     │ Silence Head   │
│ (uint32 LE)  │ (float64)   │ (float64)     │ (float64)      │
└──────────────┴─────────────┴───────────────┴────────────────┘
```

**Fields:**

| Field | Type | Description |
|-------|------|-------------|
| `total_samples` | uint32 LE | Total PCM samples produced |
| `wall_ms` | float64 LE | Total wall-clock time in milliseconds |
| `inference_ms` | float64 LE | Active model inference time in milliseconds |
| `silence_head_ms` | float64 LE | Leading silence generated by the model (ms) |

## ERROR Record

Signals an error condition. Terminal — no further records follow.

**Payload Layout:**
```
┌──────────────┬──────────────┬──────────────┐
│ Code         │ Message Len   │ Message      │
│ (int32 LE)   │ (uint16 LE)  │ (UTF-8 bytes)│
└──────────────┴──────────────┴──────────────┘
```

**Fields:**

| Field | Type | Description |
|-------|------|-------------|
| `code` | int32 LE | Terminal reason code (see below) |
| `message_len` | uint16 LE | Length of the message in bytes |
| `message` | UTF-8 | Human-readable error description |

### Terminal Reason Codes

| Value | Name | Description |
|-------|------|-------------|
| 0 | `OK` | Success (not used in ERROR records) |
| 1 | `UnknownVoice` | Voice ID not found in catalog |
| 2 | `QueueOverload` | Request queue is full |
| 3 | `WorkerUnavailable` | Worker or model not ready |
| 4 | `Timeout` | Request deadline expired |
| 5 | `ProtocolError` | Malformed data or internal error |
| 6 | `PlaybackFailure` | Audio playback failed |
| 7 | `InferenceError` | Model inference failed |

## Stream Structure

A complete response stream has the following structure:

```
START → PCM → PCM → ... → PCM → END
START → PCM → PCM → ... → ERROR  (error during synthesis)
ERROR                                   (error before synthesis started)
```

The client must handle:
- Records split across arbitrary read boundaries
- Multiple records in a single read
- Missing END records (treated as a failure)
- ERROR records at any point (terminal)

## Safety

- **Size guard**: Records claiming more than 16 MB are rejected
- **Validation**: Payload sizes are validated before allocation
- **Little-endian**: All multi-byte integers are little-endian regardless of platform
- **UTF-8**: All text is UTF-8 encoded

## Example: Complete Stream

For the text "Hello" with the default voice:

```
0x01 0x18 0x00 0x00 0x00 ...  START record (padded to 8 bytes)
0x02 0x1C 0x00 0x00 0x00 ...  PCM record #1 (480 samples)
0x02 0x1C 0x00 0x00 0x00 ...  PCM record #2 (480 samples)
0x02 0x1C 0x00 0x00 0x00 ...  PCM record #3 (remaining samples)
0x03 0x1C 0x00 0x00 0x00 ...  END record (timing metadata)
```

Total wire bytes = sum of (5 + padded payload) for each record. Each padded payload is a multiple of 8.
